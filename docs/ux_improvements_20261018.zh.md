独立复盘还补上了源会话的私有状态上下文和源快照引用，并保留源会话的失败标记，避免创建 review-only 时把不完整状态抹掉。补齐上下文后的新独立复盘用真实模型完成；此前两次上游断线依然记为失败。

抽取任务重试会保留成功记录，只重新处理失败或未完成记录，并归档前次失败检查点。源文件指纹变化时要求新建任务，避免把不同输入混入同一结果。自动化回归验证了“一条成功、一条失败 → 仅重试失败项 → 两条成功”，原始失败记录仍可追溯。

## 配置和验证边界

真实调用使用现有 `deepseek-v4-pro` 和 `text-embedding-3-large`，没有换 embedding 或重建、切换全量索引。活动索引仍是 `idx_d5b9f0077e1ca31b990080de`（1,808,415 向量、3072 维，数量来自已发布索引的既有校验）。

本机忽略的 `providers.local.yaml` 将 `llm.max_output_tokens` 从 4096 调到 8192，并显式设置 `thinking: {type: disabled}`。二者都是可改的服务参数，没有按模型名写判断。早期 8192 试验实际仍被公共抽取模板覆盖到 4096，发现后已去掉该默认覆盖，随后确认有效参数为 8192、disabled、retry_attempts=2。上游仍出现过 RemoteDisconnected，不能承诺外部服务永不失败，也不能把不同输入和设置的耗时作为受控性能对比。

所有业务输入均为 QA 合成内容。测试产生的两个课程场景最终退回，抽取候选保留为待治理；没有发布知识。测试 fixture 只用于自动化检查；实际业务验收调用真实模型。

## 后续仍需建设

1. **正式行为回归与进化门禁**：候选知识和 skill 变更应比较固定任务集的检索、工具执行、证据相关性和实际输出；现有结构/约束检查不能替代这些评估。
2. **任意 skill 的执行与界面管理**：安装、版本优化和回滚已有管理基础，但仍需补全通用运行契约、交互暂停/确认、任务恢复和 GUI，不能声称安装任意 skill 就能端到端运行。
3. **完整教学闭环**：进一步连接课程目标、场景覆盖、教师分配、学员完成、跨次学习结果及人工复核。
4. **完整双语与任务可观测性**：清理剩余旧中文界面，统一模型输出语言；增加真实阶段、排队和耗时信息，并把“连接正常”与“业务试跑成功”分开。
5. **证据与服务稳定性**：完善原始文档定位、相关性评估、多轮压力检查，以及有输入/模型/提示词版本约束的阶段检查点恢复；持续监测当前外部服务的断线情况。
