# 证据检查与可恢复的模型工作流

[English](workflow_reliability.en.md) · [工作流](workflows.zh.md) · [患者构建](simulated_patients.zh.md)

实现与测试记录见[本轮验证](workflow_validation_20261020.zh.md)。

复杂生成和评审任务已拆成有明确输入输出检查的阶段。各阶段使用当前配置的 LLM，无需增加模型服务、依赖或端口；LLM 和 embedding 继续独立配置。

## 患者与课程设计

在情景训练选择教师或研究员，输入主题，可补充患者事实。后台依次执行：规划 → 档案 → 编译场景 → 审阅 → 必要时定向修复 → 再审阅。界面展示阶段进度、历史任务和继续按钮，失败重试会复用成功步骤。

用户事实在构建场景前固定；审阅对象与最终保存的患者、公开角色卡一致。缺少审阅、带未解决错误却声称通过、空修复都不会通过。编辑或复制后旧审阅失效，可重新检查当前版本；教师明确人工覆盖时需记录理由。结构阻断项仍须修正。

课程批次先分配不同的训练目标和近期经历，再逐个构建患者。最后读取真实保存的档案，检查目标覆盖、重复事实及不充分的依据。界面显示计划和覆盖报告；修改病例后可重新检查原批次，已经保存的病例不会重做。覆盖不足的课程仍可保存为待审草稿。

## 知识抽取

确认字段和证据要求后，先试抽、预览真实输出，再明确接受结果后开始全量。也可显式选择跳过试抽并填写理由。服务器保留决定，并核对试抽与当前来源、schema 和配置是否一致；修改表单会使旧确认失效。

结构校验覆盖嵌套对象、必填字段、数组元素、类型及支持的数值/长度约束；不支持的约束会明确报错。每条引文分别对照原文，记录字符位置，一条真实引文不能掩盖另一条伪造引文。

默认语义审阅会检查抽取结论及其他生成内容是否得到证据支持；纯引文摘录可以走较短流程，选择“总是”则连这类输出也审阅。有问题时最多定向修复一次并重新审阅。仍未合格的结果留在失败记录中，保留草稿和问题，不混入成功候选。

恢复以来源记录为单位：已完成记录保留，尚未完成的记录中断后可能重新执行内部模型阶段。试抽样本覆盖来源首尾。

## 对话分析与会后复盘

对话工作区的模型评估和打包会创建后台任务；刷新可恢复输入、任务和进度。失败或中断后继续，会复用已完成窗口及工具结果。打包复用对应的评估运行；原文、角色、语言、模型、Skill 或知识变化时，不会套用旧结果。

评估会实际执行 Skill 声明的上下文和知识检索工具。发现必须提供有效轮次 ID 和原文引句；知识引用必须来自本次检索。未通过证据核对的内容单独展示，不进入已验证结论的综合。跨窗口主题引用已验证发现，界面可查看覆盖、引文、检索依据和待处理项。

模拟会谈复盘按预算分段处理完整原文，保留真实轮次 ID 和全部字符，早期与末尾问题都会进入检查；引文核验和覆盖范围随报告输出。成功分段可恢复。引文存在于原文，并不自动证明模型解释正确，报告仍可由教师复核。

## 专家任务与 Skill 改进

专家回应评审分为原文证据、六个评审维度、修改建议及独立检查。教学对话分为计划、草稿、检查和有限修复后复验。重试复用成功阶段，结果同时包含可读报告和结构化内容。教学对话长度按单条发言计数。

回应比较接收实际检索的知识正文，各候选的知识 ID 和引句都要匹配已提供内容。缺少知识时记录为依据有限，不把历史会谈中的知识 ID 当成本次生成的依据。

Skill 改进会读取选定的 Skill、引用文件、输入文本和失败证据，先诊断问题再提出局部修改；诊断结果可从检查点复用。替换 Skill 继续使用现有行为对比与人工审核门槛，生成修改稿不会自动安装。

支持助手在消息离开最近上下文时增量形成摘要，并保存已总结到的位置，避免短消息长会话遗忘早期内容或反复总结全部历史。

## 数据与当前范围

继续备份现有应用数据目录。新增数据包括患者/课程阶段检查点、对话评估任务与结果、抽取失败轨迹、专家生成检查点。这些内容随本地应用数据保存，不进入 Git 源码分发。

对话评估任务显示在对话页“最近任务”中，尚未合并到全站任务中心。专家任务已有阶段恢复，页面当前展示完成后的阶段轨迹，没有逐阶段实时进度。课程覆盖仍是一次有界的整批审阅，超过上下文预算时保持待复核。本次未给每条实时患者发言增加独立语义核验，也未重做复杂查询理解或自动批准 Skill 效果评测。
