# 关键模型工作流审查与改进顺序

后续实现与当前边界见[工作流可靠性说明](workflow_reliability.zh.md)。下文保留修复前的审查基线。

审查日期：2026-10-19。代码基线：`a4979df`（`Use staged agentic patient generation`）。

**接下来应优先补齐证据核验、修复后复验和阶段恢复。** 当前已经有多种工作流；模型调用次数增加，本身并不能证明产出更可靠。适合离线完成的抽取、评审、患者设计、课程编排和 Skill 改进可以更细致；实时支持和模拟对话需要保留简短的响应路径。

本轮检查了 Python 执行路径、API、相关界面调用及已有测试，并以合成输入在本地复现了 6 项问题。没有调用真实模型，没有进行本轮浏览器验收，也没有修改业务实现。下文区分已复现缺陷与从代码确定的功能缺口。

## 优先级与范围

P0 表示先消除错误的通过状态或证据标识；P1 表示补全核心功能；P2 表示提升复杂任务质量。这里的排序是本项目的开发顺序。

| 功能 | 当前实际流程 | 主要缺口 | 优先级 |
| --- | --- | --- | --- |
| 模拟患者设计 | 规划 → 患者档案 → 场景包 → 审阅 → 可选修复 | 空审阅可被当作通过；空修复也标记通过；未复验；用户事实在审阅后覆盖 | P0 |
| 知识抽取与治理 | 外层已有计划、试抽、全量、治理、索引及恢复；每条记录内仍主要一次生成 | 嵌套 schema 和逐条引文核验不足；复杂记录没有语义审阅与定向修复 | P0 / P1 |
| 对话分析、训练复盘 | 对话分析按 Skill × 窗口生成；训练复盘调用摘要和 reviewer | 工具声明未真正执行；失效引用仍保留；复盘直接输入只覆盖尾部；缺跨窗综合 | P0 / P1 |
| 专家评审、教学对话、三种回应比较 | 先路由检索，再用一次调用生成多项结果；有任务重试 | 缺少业务专属输出约束；回应比较所附知识 ID 未进入模型输入 | P0 / P1 |
| 批量课程场景 | 逐个生成、检查、保存，已有批次任务和失败重试 | 没有课程覆盖规划；各案例缺少明确分工及批次整体复核 | P1 |
| 实时支持与患者模拟 | 支持已有路由/检索；模拟已有行为理解、披露编译、回复、后台状态和记忆 | 支持短消息长会话有上下文空档；患者话语未独立核对事实；次级 Skill 主要作为标签 | P1 |
| Skill 优化与行为评测 | 单次生成修改稿；已有实际执行评测、基线比较和人工复核门槛 | 修改前缺少失败诊断，UI 输入材料未使用；评审稳定性仍需验证 | P2 |
| 查询理解与检索 | 已有确定性规范化、概念扩展、功能路由与过滤 | 复杂歧义、组合请求和证据不足时的处理需专项验收 | P2 |

## 1. 患者设计：先保证审阅确实约束结果

当前四个固定阶段已经降低了单次生成的负担，但还不是能够逐阶段恢复的任务。

- **已复现：**审阅返回 `{}` 时，`review_status` 默认为 `pass`。
- **已复现：**审阅提出 error，修复返回 `{}`，仍被标记为 `pass_after_repair`，且没有第二次审阅。结构质量报告也没有因此失败。
- **已复现：**用户指定的近期经历在审阅完成后覆盖模型生成的经历，导致实际保存的患者与审阅对象不同。原始用户输入虽然也在提示中，但没有用代码保证各阶段的患者事实一致。
- **代码确认：**批准端点只检查确定性质量报告，未将模型审阅未完成或未解决的问题纳入批准约束。中间阶段仅保存在内存，最后才写场景版本；外层通用 Task 只在整个工具调用结束后保存结果。

改进流程：固定用户事实 → 设计计划 → 档案生成 → 场景构建 → 对最终候选审阅 → 按问题修复 → 再审阅 → 保存草稿。每阶段有明确 schema 和检查点；达到修复次数上限后保留待处理草稿。人工批准时展示仍未解决的问题；如允许人工覆盖，需要单独记录理由。

依据：[生成器](../domains/theraskill/theraskill_simulation/scenario_generation.py#L286)、[修复状态](../domains/theraskill/theraskill_simulation/scenario_generation.py#L336)、[用户事实覆盖](../domains/theraskill/theraskill_simulation/scenario_generation.py#L430)、[批准条件](../domains/theraskill/services/simulation_api/app.py#L846)、[通用工具调用检查点](../theraskill_agent/task_runtime.py#L231)。

## 2. 知识抽取与治理：落实到每条结论、每条证据

已有外层流程值得继续使用：计划确认、小样本审核、全量执行、候选治理、索引和评测后激活；逐记录检查点、失败重试和幂等交接也已存在。

- **已复现：**数组内对象缺少 schema 要求的 `evidence`，同时 `confidence=2` 超出 `maximum=1`，当前验证仍返回无错误。
- **已复现：**同一字段路径下，一条真实引文与一条原文不存在的引文混合，证据报告仍为 `pass`。目前逻辑使用 `any` 命中，没有逐条绑定。
- **代码确认：**`plan.operations` 没有驱动分阶段执行；每条记录通常一次生成，然后做有限的结构与引文检查。引文出现于原文也不代表它支持抽出的结论。
- **代码确认：**计划检查样本已采用分散采样，但执行试抽仍取前 N 条。UI 允许计划确认后直接全量执行，Task 路径则要求确认试抽结果。
- **代码确认：**治理结构化有长文分块，但最终改写缺少对原始证据的语义复核。现有发布门槛另有检索 canary 和人工审核；部分名为 regression 的检查实际只验证结构与字段非空。

先修递归校验与逐条引文定位。复杂记录再走“证据定位 → 候选抽取 → 结论与证据核对 → 修复”，简单记录保留较短流程。统一 UI/Task 的计划与试抽确认，展示试抽覆盖范围。治理增加改写前后的事实/范围核对，以及待发布批次内部的重复、互补和矛盾检查。

依据：[结构校验与引文核验](../theraskill_agent/extraction/executor.py#L82)、[逐记录生成](../theraskill_agent/extraction/executor.py#L168)、[抽取界面](../views/theraskill/workbench/src/ExtractionStudio.tsx#L77)、[治理结构化](../domains/theraskill/theraskill_contribution/candidate.py#L183)、[治理结构回归](../domains/theraskill/theraskill_contribution/candidate.py#L322)。

## 3. 对话分析与复盘：覆盖全文，并真正执行所需工具

两种入口有不同的问题：

- 对话文件评估已经按 Skill 和窗口多次调用。计划中的 `required_tools` 只是元数据；实际执行器拼接 Skill 文本直接调用模型，没有执行其中要求的 context/knowledge search。
- **已复现：**finding 的 turn ID 全部无效时，只记录 warning，finding 及其 `pass` 状态仍保留；需要清楚区分未证实的观察与有原文依据的结论。
- 对话分析输出明确保留分窗结果，尚无跨窗口综合；API 的打包入口会重新执行评估，缺少逐窗口持久结果复用。
- 训练会后复盘虽有摘要和 reviewer 两次调用，两者的直接原文输入都只取最后 10 条发言，每条最多 220 字符，外加最后 4 条 turn record。更早内容只有在模型记忆保留时才可能进入评审。

建议统一为：原文与角色确认 → 证据分段 → 按维度加载 Skill 和检索量规 → 分段评审 → 引用校验 → 跨段综合 → 冲突或无依据结论复核。记录已覆盖的原始 turn ID；无法覆盖的内容要明确展示。会后任务允许慢一些，实时对话不承担这整套流程。

依据：[评审计划与执行](../theraskill_agent/reviews.py#L90)、[引用处理](../theraskill_agent/reviews.py#L143)、[分窗综合状态](../theraskill_agent/reviews.py#L220)、[摘要输入](../scripts/Simulation/run_session_longitudinal_summary.py#L58)、[reviewer 输入](../scripts/Simulation/run_session_reviewer_gate.py#L59)、[API](../domains/theraskill/services/transcript_api/app.py#L79)。

## 4. 专家工作台与回应比较：分别设计任务输出

专家评审和教学对话已有明确路由、知识检索、异步任务与重试，但主要复用 Support 的一次 response 生成。非空 `response_text` 校验不能保证多维评审、完整教学对话及其解释都已经完成。

三种回应比较也一次生成全部候选，当前只要求 3 条非空 response。代码中的 `evidence_unit_ids`、`knowledge_release_id` 没有进入这次生成的模型 payload，而是在结果上附加；不能据此判定这些候选实际使用了对应知识。

建议分成三个业务流程：

- 回应评审：提取原文证据 → 分维度审阅 → 汇总问题 → 生成修改建议 → 核对建议是否解决问题。
- 教学对话：明确教学目标和互动计划 → 分段生成 → 检查角色、策略、事实和教学目标 → 局部修订。
- 回应比较：规划不同策略 → 各自检索与生成 → 独立比较适用情境和限制，保存实际使用的证据。

依据：[专家任务构造](../domains/theraskill/services/expert_api/app.py#L154)、[共享生成与校验](../domains/theraskill/theraskill_support/engine.py#L361)、[三种回应生成及证据字段](../domains/theraskill/theraskill_simulation/training.py#L333)。

## 5. 课程批量生成：先规划课程，再生成病例

现有批次会逐病例保存、检查并支持失败重试。差异化主要来自提示中的“第 N 个，改变触发情境或目标”，没有预先给病例分配训练目标、难度梯度及经历组合。

建议先生成可修改的课程覆盖表，明确每个病例的目标、经历、策略练习和难度，再调用患者生成流程。全部完成后核对覆盖、难度分布与内容相似性，只重做不足的病例。UI 增加计划预览和覆盖结果，继续使用现有批次进度与重试入口。

依据：[批次执行](../domains/theraskill/services/simulation_api/app.py#L331)、[差异提示](../domains/theraskill/services/simulation_api/app.py#L357)。

## 6. 实时对话：重点是记忆与事实一致性

模拟患者已使用“理解治疗师行为 → 编译允许披露的事实 → 生成回复 → 后台状态和记忆更新”。状态更新未结束会阻止下一轮，也支持失败重试。无需为了形式上的 agentic 而给每轮增加大量调用。

仍应处理三项代码中明确的缺口：

1. 支持助手总历史不足压缩阈值时，只取最近 10 条历史消息，之前的短消息可能在没有摘要时退出上下文。应在移出窗口时增量更新记忆，并保存已处理消息位置。
2. 模拟回复的校验主要过滤模型报告的事实 ID，实际说出的文本不会因非法 ID 被过滤而自动修复。需要检查话语与可用事实的一致性，异常时局部重试。
3. 支持路由的 `secondary_skills` 没有独立加载相应指导和知识。应明确它只是建议标签，还是确实需要执行的子任务；复杂复合任务可以转到后台工作流。

依据：[支持历史窗口](../domains/theraskill/theraskill_support/engine.py#L259)、[患者生成与事实 ID 过滤](../domains/theraskill/theraskill_simulation/engines.py#L603)、[状态更新约束](../domains/theraskill/theraskill_simulation/service.py#L864)、[次级 Skill](../domains/theraskill/theraskill_support/engine.py#L181)。

## 7. Skill 改进与检索：让评测决定是否增加复杂度

Skill 改进目前一次生成整份修改稿，只传入 goal、原 Skill 和语言；界面发送的 `inputs.text` 没有被这个分支读取。已有实际行为评测、版本绑定、基线比较和人工复核门槛，应保留并接到修改过程中。

目标流程：导入失败案例与报告 → 判断是提示、知识、工具还是上下文的问题 → 最小范围修改 → 原版与候选运行同一组用例 → 检查退步 → 继续修订或提交审核。单一 Judge 打分的稳定性需要实测，重要案例可独立复核。

查询理解目前已具备规则规范化、概念扩展、按功能选知识家族和过滤；`needs_clarification` 主要依据是否提取到词项。后续应用真实任务检查歧义与复合意图，只在必要时加入模型澄清或子查询规划。是否改进，以证据相关性、覆盖和耗时共同判断。

依据：[Skill 修改](../theraskill_agent/task_runtime.py#L215)、[界面输入](../views/theraskill/workbench/src/WorkflowStudio.tsx#L22)、[替换门槛](../theraskill_agent/skills.py#L238)、[行为评测](../theraskill_agent/behavior_eval.py#L127)、[查询理解](../theraskill_agent/query_understanding.py#L230)。

## 实施顺序与验收

**第一轮：纠正通过状态和证据关联。** 修复患者空审阅/空修复及审阅后覆盖、递归 schema 和逐引文检查、评估的无效引用、回应比较的知识来源记录。验收用不完整 JSON、空修复、伪造引文、无效 turn ID，以及用户事实冲突这些确定性样例。

**第二轮：补全核心长任务。** 全文复盘、真实 Skill 工具执行、复杂记录抽取、支持会话增量记忆、课程覆盖规划。阶段结果写入现有任务存储；刷新、进程重启、单阶段失败后恢复时复用已有结果，重试不得重复创建场景或候选。

**第三轮：用行为证据优化。** 专家任务细分、教学内容复核、Skill 诊断修改、复杂查询处理。用相同的中英文任务分别验证本地模型与配置的远程模型，记录覆盖、未解决问题、模型调用量和耗时；比较完整任务产出质量。

共同执行方式：扩展现有 TaskEngine 的阶段状态和结果存储；业务服务负责各自的输入输出规则；需要澄清或动态选工具时由 Agent 决策。UI 展示当前阶段、待确认问题、原文依据、结果版本与失败重试。复用现有服务入口，不为每个阶段新增端口或服务。
