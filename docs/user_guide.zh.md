# TheraSkillAgent 图文使用指南

本指南按心理专业人员的一次实际工作顺序编排：配置模型、向助手提出工作、整理对话、查找或建设知识、创建模拟患者、组织课程与检查结果。截图来自 2026-10-27 的隔离项目；界面文字以当前中文模式为准。示例均为虚构、去标识化材料。安装与迁移另见[部署说明](deployment.zh.md)和[资源安装说明](resource_installation.zh.md)。

## 先打开工作台

1. 启动 `theraskill-agent ui`，在浏览器打开 <http://127.0.0.1:5176/>。整个网页和业务接口共用这一个入口。新安装的设备先在首页的「使用准备」查看模型、知识、模拟情景和 Skill 的状态。
2. 日常工作从顶部「助手」开始；已经确定要处理对话、知识或课程时，可直接进入对应工作区。「任务与历史」保存可恢复的执行记录，不是普通聊天列表。
3. 右上角 `EN` / `中文` 切换界面与新任务的输出语言；原文材料和已有历史不会被翻译。

![工作台和主要入口](images/user-guide/01-home.png)

## 1. 配置并测试模型

1. 点击顶部「模型与连接」。LLM 用于对话、规划、生成和评阅；Embedding 用于语义索引与检索，两者的模型名、地址和密钥可以不同。
2. 分别填写模型名、Base URL 和 API key。Embedding 服务如需单独的 `/embeddings` 地址，填入 `Embedding endpoint`。已配置的密钥显示为圆点；不修改密钥时留空即可。
3. 点击「测试当前配置」。看到 LLM 和 Embedding 都为 `ok`，再点「保存配置」；也可以一次点击「测试通过后保存」。保存到当前项目的本机配置文件，修改后重启应用进程。

![分别配置两类模型](images/user-guide/02-models.png)

![隔离实例中两种模型的真实连接测试](images/user-guide/16-model-test.png)

连接测试会发起真实模型请求。只有快速查找知识和确定性文本检查可以不使用模型；生成、评阅和语义索引仍需相应服务可用。

## 2. 向助手描述一项工作

1. 点击顶部「助手」或首页「打开助手」，用「新对话」开始。可以直接写目标，也可以粘贴已去标识化的会谈片段。例如：`请从督导角度讨论这段虚构会谈……给出两种开放式提问并说明目的。`
2. 发送后等待回应。简单问候和明确的产品操作问题通常走较轻的路径；专业问题可能检索知识，耗时会更长。示例回应给出了提问、各自目的，以及信息不足之处。
3. 回应下方若出现「参考依据」，点击条目可读知识内容和来源，再进入知识编辑。若显示「本轮未找到可用参考依据」，表示这轮没有可用的检索命中，不应把回答表述成已有知识证明的结论。
4. 点赞/点踩可以记录反馈；会话保留在左侧列表，顶部可导出或结束。正式材料先去标识化，确认模型服务的数据处理约定后再发送。

## 3. 整理对话文件

1. 从工作台进入「打开对话分析」。粘贴文本，或用「读取本地文件」选择 TXT、Markdown、JSON、CSV、SRT 或 VTT。输入语言可以保持自动识别；原文不会因界面语言切换而改写。
2. 先点「检查格式」。检查轮次、说话人、混合语言和疑似转录问题；如角色未确认，在右侧把说话人映射为来访者或咨询师。
3. 点「确定性分析」得到不调用模型的结构和质量信息。需要更深入的过程、回应和风险审阅时再点「多 skill 评估」，选择审阅范围，确认生成的计划后执行。
4. 最后点「生成 bundle」，下载包含规范化轮次、来源位置、审阅结果和原文证据的 ZIP。对语音转录错字先核对原音或原稿；系统保留原文，模型推断不能替代核实。

## 4. 查找已有知识，查看详情

1. 从工作台进入「知识与索引」的「查找知识」。输入一个具体问题，并在「用于哪个功能」选择支持对话、模拟情景、回应审核等用途；不同用途限定不同知识范围。
2. 点击「查找」。列表先展示简短内容；「全文与来源类型」可展开索引文本，「查看与编辑知识」可打开原始字段、来源、适用情境和使用边界。
3. 历史检索任务重新打开时会恢复原问题、功能、语言和索引。检索命中只是候选依据，必须看原文、来源和适用范围。这轮在完整索引上的「首次会谈如何回应焦虑」查询仍出现相关性较弱的回应示例，不宜照单全收。

## 5. 安装知识并建立索引

第一次体验可使用项目自带的 `examples/knowledge/demo.jsonl`，先不安装大型资源：

1. 在「知识与索引」切到「添加知识」，用「上传 JSONL」选择样例文件，或选择已安装的知识。正式知识资源是一份可直接安装的 ZIP；大型包更适合按[资源安装说明](resource_installation.zh.md)使用命令行安装。
2. 「查找方式」先选「快速搜索（无需模型服务）」，点击「构建可检索版本」。后台任务会显示进度；刷新页面后可在「管理版本」找回。小样例实测完成构建、校验、启用和检索。
3. 在「管理版本」点击「验证」。空项目首次启用可直接点击「启用」；已有活动版本时，须先做同一组案例的效果比较与人工复核。原版本不会因构建新版本而自动替换。
4. 需要语义检索时再选「智能匹配」，确认 Embedding 连接和预估工作量。更换 Embedding 模型时，已有向量索引不会自动兼容，须建立对应版本。

![添加知识与选择构建方式](images/user-guide/05-knowledge.png)

![隔离空项目完成小样例索引构建](images/user-guide/fresh-index-built.png)

![小样例索引的检索结果](images/user-guide/fresh-index-search.png)

完整 Phase 6 知识包的实测为 2,196,286 条输入、1,808,415 条可索引记录；首次全量词法构建远慢于小样例，需预留本地高速存储和时间。完整包及预构建索引不包含在源码仓库中。

## 6. 修订一条知识

1. 在助手的「参考依据」或知识搜索结果点开条目，先核对索引摘录与原始字段是否一致。
2. 点击「编辑知识」，修改标题、摘要或适用边界，保存为草稿。草稿不会静默改写旧回复或正在使用的索引。
3. 点「重新生成索引」，在「管理版本」跟踪候选构建、校验及效果比较。只有通过版本门禁并确认启用后，新知识才进入正式检索。大型来源的重建可能较久。

![真实条目的草稿修改与候选索引任务](images/user-guide/knowledge-edit-reindex-focus.png)

## 7. 从材料抽取知识并交给审核

1. 从工作台进入「打开知识抽取」，上传已授权的文本，或填写服务器上可访问的输入文件路径。点「检查输入」，先读记录数量与原文样本，确认编码、切分和来源无误。
2. 写清抽取目标，例如「提取咨询师回应中有逐字证据支持的开放式提问策略」。点「让模型建议字段与计划」。检查抽取单元、输出字段、必填项及证据要求；可以在表单里修改，JSON 只放在高级区域。
3. 勾选确认后执行「小样本试抽」。在右侧点「预览候选」，逐项核对结论/策略、原文引句和核验状态。接受试抽后才能启动全量；明确跳过试抽必须留下理由。
4. 全量结束后仍要预览，满意时点「交给治理」。这一步生成候选，不等于批准发布；后续转到专家工作台做结构、重复度、证据和适用性审核。

## 8. 专家审阅与知识治理

1. 从工作台进入「打开专家工作台」。顶部可切换「回应审核」「知识贡献」「反馈审阅」「内容实验室」「案例工作区」。选择本地工作角色后，再开始对应任务。
2. 抽取候选由「交给治理」链接进入知识贡献/候选治理；先看结构化内容与原文证据，再处理重复、冲突、退回或审定。只有有资格的审核者才应执行正式批准与发布。
3. 「回应审核」可提交咨询师回应或会谈上下文，查看质量、边界和证据意见；模型审阅是辅助意见，不替代督导。用户反馈审阅也在同一工作台保留处理记录。

## 9. 构建模拟患者并训练

1. 进入「打开情景控制台」。学员从场景库选择已批准的情景并点「开始训练」；教师或研究员可切换角色，打开「构建模拟患者」。
2. 写训练主题、难度与风险。在线生成会按规划、患者档案、场景、审阅等阶段运行；也可以手工填档案并保存。档案包括近期经历、发生时间、影响、隐藏顾虑与披露层级。
3. 打开「查看和编辑患者档案」，修改后保存新版本。旧会谈固定使用创建时的版本；新会谈使用新版本。「查看知识来源」可跳转到真实知识详情；旧场景若只有来源编号，仍可通过该链接读取条目。生成草稿需教师检查问题和重复度，再决定是否批准复用。
4. 在场景中选训练角色，开始会谈并逐轮回应。会谈完成后查看复盘与训练记录；对高风险场景仍需人工监管。

## 10. 设计课程、学员练习和教师反馈

1. 在「课程与学习进展」切换教师视角。先与课程 Agent 讨论目标、对象和需要的病例；确认计划后，可从课程起点修改目标、可观察行为、知识卡、微练习和评分描述。
2. 选择已审核场景，或按课程目标批量生成患者。逐个检查目标覆盖、风险、难度和重复度，批准后保存为课程；用学员标签分配。无需为试用创建账号。
3. 切换学员视角，输入教师给的标签并点「加载进展」。先看知识卡，针对一段来访者情境提交短回应和反思，然后点「获取 AI 反馈」。可以带着这个目标进入完整模拟会谈。
4. 教师再打开同一学员的练习，阅读学员原话、模型依据及评分理由，独立填写观察与结论。模型分数是教学反馈，不是临床胜任力认证；提示使用、量规和案例难度会影响可比性。

## 11. Skill、任务与历史

1. 从工作台进入「自动化任务」。给 Agent 一个明确目标，可选已安装 Skill，粘贴文本或上传文件后点「创建并运行」。Skill 是可复用的方法，Task 是这一次执行；工作区是面向人的业务入口。
2. Agent 需要确认说话人、抽取 schema 或写入操作时，任务会暂停等待回答/批准。打开「进度与交互」处理问题、查看工具记录；失败任务可保留检查点再重试。
3. 顶部「任务与历史」汇总运行中、待处理、已完成和已归档的任务。普通助手对话不在这里。Skill 目录与运行依赖可在自动化任务页检查；替换已安装 Skill 需要相同案例的效果对比和批准。

## 12. 发布前检查

1. 从工作台进入「发布前效果检查」。先用同一组案例和量规建立当前版本的基线，再运行候选索引、Skill 或内容版本的比较。
2. 查看每条案例的实际输出、引用、失败原因和相对基线变化，再填写人工结论。配置、知识或评价器改变后，旧报告不能继续用于放行。
3. 门禁通过只表明这组案例下未发现超限回归；不能由模型评分推断临床有效性。没有足够的基线或人工复核时，页面阻止正式晋级属于预期行为。

## 本轮验收边界

上述入口均在桌面浏览器打开，未出现脚本错误或横向溢出；核心流程在隔离数据中实际执行。模型测试、助手问答、全文检索、试抽、场景生成和训练、课程练习与 AI 评阅都调用了真实配置。指南中的截图随源码保存在 `docs/images/user-guide/`。正式专家身份核验、人工审定和上线批准未用测试身份冒充完成。完整知识库的检索相关性仍需针对各业务功能继续标注和评价。
